## 1. VIBE 플레이리스트가 이름별로 나뉘지 않음

**증상**
- 보관함의 플레이리스트(운동 / ☠ / 국내 / 인디 / 느좋 RnB 등 / 락 / 국힙&외힙 / Jpop)가 따로 저장되지 않았습니다.
- 결과 파일에는 두 항목만 있었고, 이름이 둘 다 `보관함 > 플레이리스트 VIBE(바이브)`였습니다.
  - 첫 번째 항목(운동 11곡)은 정확했습니다.
  - 두 번째 항목(☠ 페이지)에는 보관함의 모든 곡 257곡이 섞여 있었습니다.

**원인**
- 이름을 정할 때 플레이리스트 이름이 아니라 브라우저 탭 제목을 썼습니다.
- ☠ 페이지에서 그 플레이리스트 전용 곡 목록 응답을 찾지 못하면, 그동안 받은 곡을 모두 합치도록 되어 있었습니다. 보관함 목록 화면이 모든 플레이리스트의 곡을 한꺼번에 받아오는데, 그게 그대로 섞였습니다.

**해결**
- 보관함 → 플레이리스트 목록 화면에서 Enter를 한 번 누르면, 각 플레이리스트를 자동으로 열어 **따로** 저장합니다.
- 이름은 목록 카드에 적힌 이름을 씁니다.
- 플레이리스트 페이지에서는 그 플레이리스트의 응답만 씁니다. 못 찾으면 한 번 새로고침해서 다시 찾고, 그래도 없으면 다른 곡을 섞지 않고 건너뜁니다.
- 이름이 겹치면 `(2)`를 붙여서 Spotify로 보낼 때 합쳐지지 않게 했습니다.

**확인**: 다시 실행한 결과, 8개 플레이리스트가 각각 저장됐습니다.

## 2. VIBE 국힙&외힙이 128곡 중 100곡만 저장됨

**증상**
- 다른 플레이리스트는 곡 수가 모두 맞았습니다: 운동 11, ☠ 5, 국내 5, 인디 96, 느좋 RnB 등 21, 락 26, Jpop 9.
- 국힙&외힙만 128곡 중 100곡이 저장됐습니다.

**원인 (추정)**
- VIBE 화면이 곡 목록을 100곡씩 나눠 받는데, 첫 100곡만 받고 스크롤해도 나머지를 더 요청하지 않았습니다.

**해결**
- 가져온 곡 수가 카드에 적힌 `N곡`이나 응답에 있는 전체 곡 수보다 적으면, 나머지 곡을 VIBE에 직접 이어서 요청합니다. 로그인 상태는 그대로 씁니다.
- 그래도 모자라면 `N곡 중 M곡만 가져왔습니다` 경고를 출력합니다.

**남은 확인**
- 실제 VIBE에서 `국힙&외힙: 128곡`으로 나오는지 확인해야 합니다.
- 경고가 뜨면 아래 명령의 결과를 공유해 주세요.
  ```powershell
  Select-String -Path output\raw_vibe\*.json -Pattern "74895550" -List | ForEach-Object { (Get-Content $_.Path -TotalCount 1) }
  ```

## 3. 벅스 실행 시 "요청하신 페이지를 찾을 수 없습니다"

**증상**
- `bugs` 명령을 실행하면 벅스 404 화면이 열렸습니다.

**원인**
- 처음 여는 주소를 추측해서 넣었는데(`music.bugs.co.kr/user/library`), 실제로는 없는 페이지였습니다.

**해결**
- 처음 여는 주소를 벅스 홈(`music.bugs.co.kr`)으로 바꾸고, 안내 문구를 "내 음악 → 내 앨범"으로 고쳤습니다.
- 곡 수집은 Enter를 누를 때 보고 있는 페이지에서 하므로, 수정 전 버전에서도 직접 내 앨범으로 이동하면 사용할 수 있습니다.

**남은 확인**
- 벅스 곡 목록 화면 구조(`tr[rowtype="track"]`, `p.title`, `p.artist`, `a.album`)는 아직 실제 사이트에서 확인하지 못했습니다. 앨범 하나로 먼저 확인해야 합니다.
- 곡을 못 찾으면 `output\raw_bugs`에서 가장 최근 `..._page.html` 파일을 공유해 주세요.

## 4. Windows 설치 오류

**증상**
- `.venv\Scripts\Activate.ps1`을 실행하면 "이 시스템에서 스크립트를 실행할 수 없으므로…" 오류가 났습니다.
- `pip install -e .`를 실행하면 `neither 'setup.py' nor 'pyproject.toml' found` 오류가 났습니다.

**원인**
- PowerShell 기본 설정이 스크립트 실행을 막고 있었습니다.
- 명령을 프로그램 폴더가 아니라 사용자 폴더(`C:\Users\<이름>`)에서 실행했습니다.

**해결**
```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
cd "C:\Users\<이름>\Downloads\playlist-extractor-main"   # pyproject.toml 이 있는 폴더
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e .
python -m playwright install chromium
```
- 탐색기에서 프로그램 폴더를 열고 주소창에 `powershell`을 입력하면, 그 폴더에서 PowerShell이 바로 열립니다.
- `pip install -e .`로 설치했기 때문에, 새 버전 ZIP을 받아 덮어쓰기만 해도 바로 반영됩니다. 다시 설치하거나 PowerShell을 다시 켤 필요가 없습니다.

## 5. Spotify 앱 등록 시 입력값

| 항목 | 값 |
|---|---|
| 웹사이트 | 비워도 됩니다 |
| 리디렉션 URI | `http://127.0.0.1:8888/callback` (`localhost`가 아니라 `127.0.0.1`, `https`가 아니라 `http`) |
| 사용할 API | 웹 API |

저장한 뒤 앱 설정 화면에서 **Client ID**를 복사해서 `$env:SPOTIFY_CLIENT_ID="..."`로 넣습니다. Client Secret은 쓰지 않습니다.

## 6. 벅스 '최근 들은 곡' 등 여러 페이지 목록 추출 (기능 요청)

**요청**
- 벅스 '최근 들은 곡'은 목록이 1, 2, 3 … 10 페이지로 나뉘어 있는데, 이것도 한 번에 추출하고 싶다는 요청이었습니다.

**구현**
- 곡 목록 페이지에서 Enter를 누르면, 페이지 번호 영역(`.paging` 등)의 번호를 2, 3, 4 … 순서로 눌러 마지막 페이지까지 모읍니다.
- 번호가 10개씩 묶여 있으면 '다음' 버튼을 눌러 다음 묶음(11~20 …)으로 넘어갑니다.
- 중간 페이지에서 시작하면 '1' 또는 '처음'/'이전' 버튼으로 1페이지로 돌아간 뒤 처음부터 모읍니다.
- 다음 번호가 없거나, 새 곡이 없는 페이지가 나오면 멈춥니다. 페이지마다 진행 상황을 출력합니다.
- 내 앨범 곡 목록이 여러 페이지인 경우에도 똑같이 동작합니다.

**남은 확인**
- 실제 벅스 페이지 번호 영역의 구조는 아직 확인하지 못했습니다. 페이지가 넘어가지 않으면 `output\raw_bugs`에서 가장 최근 `..._page.html` 파일을 공유해 주세요.

## 7. Spotify `match` 실행 시 403 "Insufficient client scope"

**증상**
- Spotify 로그인은 성공했는데, 첫 곡을 검색하자마자 아래 오류로 멈췄습니다.
  ```
  GET https://api.spotify.com/v1/search?...&market=from_token → 403 {"error": {"status": 403, "message": "Insufficient client scope"}}
  ```

**원인 (추정)**
- 검색할 때 `market=from_token`(로그인한 사용자 계정의 국가로 검색)을 썼습니다. 그런데 계정 국가를 읽는 권한(`user-read-private`)을 요청하지 않았습니다.

**해결**
- 로그인할 때 `user-read-private` 권한도 함께 요청합니다.
- 검색 국가를 `KR`로 명시합니다. 다른 국가로 검색하려면 환경변수 `SPOTIFY_MARKET`으로 바꿀 수 있습니다(예: `$env:SPOTIFY_MARKET="JP"`).
- 저장된 로그인 정보(`.spotify_token.json`)에 새 권한이 없으면 자동으로 다시 로그인합니다. 업데이트 후 첫 실행에서 Spotify 동의 화면이 한 번 더 뜨는 것은 정상입니다.

**확인**: 업데이트 후 곡 검색과 매칭(`✔`/`✘`)이 정상으로 진행되는 것을 확인했습니다.

## 8. 피처링이 긴 곡에서 400 "Query exceeds maximum length" 로 `match` 중단

**증상**
- 매칭을 진행하다가 아래 곡에서 오류가 나며 전체가 멈췄습니다.
  - 곡: `Achoo Remix (Feat. 미란이(Mirani), pH-1, 먼치맨, … 휘민 (Lil Moshpit), Khakii (카키))`
  - 오류: `400 {"error": {"status": 400, "message": "Query exceeds maximum length of 250 characters"}}`

**원인**
- 검색어를 만들 때 제목에서 `(Feat. …)`를 지우는데, 괄호 안에 괄호가 또 있으면(`미란이(Mirani)`) 첫 번째 닫는 괄호에서 멈춰서 나머지가 남았습니다. 그 결과 검색어가 Spotify 제한(250자)을 넘었습니다.
- 검색 오류가 곡 하나에서만 나도 `match` 전체가 중단됐습니다.

**해결**
- 괄호 짝을 세어서 `(Feat. …)` 괄호를 안쪽 괄호까지 통째로 지웁니다. 위 곡은 `Achoo Remix`로 검색합니다.
- 검색어의 제목은 150자, 아티스트는 60자로 자르고, 전체 길이도 250자를 넘지 않게 했습니다.
- 곡 하나에서 검색 오류가 나도 그 곡만 `✘`로 남기고 다음 곡으로 계속 진행합니다.

## 9. ✘(못 찾음)가 너무 많음 / 가장 비슷한 곡으로 넣기 (요청)

**증상**
- 중간에 멈춘 결과 기준으로 VIBE 230곡 중 90곡이 ✘였습니다. 특히 카더가든, QWER, 잔나비, 예빛, 혁오처럼 **한국어 제목** 곡이 많았습니다.
- 반대로 **틀린 곡이 ✔로 잡힌** 경우도 있었습니다.
  - `뻔한 멜로디 (Feat. Crush)` → `Eat`
  - `불 꺼진 방 안에서 (feat. 윤석철)` → `Eat`

**원인 (match.csv 분석)**
- Spotify에는 국내 곡이 **영문·로마자 제목**으로 올라간 경우가 많습니다. 예: `위잉위잉` → `Wi ing Wi ing`, `검색어는 QWER` → `#QWER`, `뿌리` → `The Roots`, `여백의 미` → `The Beauty of Void`. 아티스트 필터 검색으로 곡은 찾아오는데, 제목이 달라서 유사도 비교에서 탈락했습니다.
- 아티스트가 `혁오(HYUKOH)`, `GRAY (그레이)`처럼 '한글(영문)' 꼴이면, 그대로 검색했을 때 못 찾는 경우가 있었습니다.
- `Eat` 오매칭은 버그였습니다. 짧은 단어 `eat`가 `(Feat. …)`의 `feat` 안에 포함돼 있다는 이유로 높은 점수를 줬습니다.

**해결**
- **한국어 표기로 받기**: 검색할 때 `Accept-Language: ko`를 보내서, Spotify가 제공하는 경우 한국어 제목·아티스트명을 받습니다. 바꾸려면 `SPOTIFY_LOCALE`을 쓰세요.
- **아티스트 표기 나눠서 검색**: `혁오(HYUKOH)` → `혁오(HYUKOH)` / `혁오` / `HYUKOH` 순서로 검색합니다.
- **제목 비교 강화**
  - 괄호 안팎을 따로 비교합니다. 예: `노래` ↔ `노래 (The Song)`, `그냥 (Just)` ↔ `Just`
  - 한글 제목은 로마자로 바꿔서도 비교합니다. 예: `위잉위잉` ↔ `Wi ing Wi ing`, `쿵` ↔ `Kung`
- **제목만으로 검색**: 그래도 없으면 `track:"제목"`만으로 검색해서, 아티스트가 비슷한 곡을 고릅니다.
- **△ 추정**: 확실한 곡이 없으면 가장 그럴듯한 후보를 △로 넣습니다. 후보는 아티스트 필터 검색에서 Spotify가 1위로 올린 곡이거나, 제목·아티스트가 50% 이상 닮은 곡입니다.
  - CSV에는 `method=guess`로 표시됩니다.
  - `push`는 △ 곡을 기본으로 포함하고, `--exclude-guesses`를 붙이면 뺍니다.
- **오매칭 수정**: 짧은 쪽 길이가 긴 쪽의 절반 이상일 때만 '포함' 점수를 줍니다.
- **중복 제거**: 같은 Spotify 곡으로 매칭된 곡이 한 플레이리스트에 여러 개 있으면 한 번만 넣습니다.

**남은 확인**
- 다시 `match`를 실행해서 ✘가 얼마나 줄었는지, △ 추정이 맞는 곡인지 확인해야 합니다.
